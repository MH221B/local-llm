# Phase 1 — Teacher inference & SFT dataset generation

**Status:** design approved, revised after external review, revised 2026-09-29 for prompt-only teacher distillation, implementation not started
**Companion docs:** `bench/qwen35-mtp/PIPELINE.md` (Phase 1 section), `bench/qwen35-mtp/results.md`

**Terminology:** Phases 1–4 follow `PIPELINE.md`. M1–M3 are the milestones *inside*
Phase 1. "Stage 1" and "Stage 2" in `PIPELINE.md` are Phase 2A and 2B.

---

## 1. Goal

Produce the supervised fine-tuning dataset that Phase 2A trains on, for
`Qwen3.5-4B-MTP-Heretic`. The prebuilt corpora supply **user prompts only**; the
abliterated Ornith 9B writes **every response**, and unit-test / gold-answer seeds filter
the teacher's failed attempts before they can reach the student.

The dataset covers four domains (Reasoning & Math, Coding & Agentic, Roleplay &
Conversational, Uncensored & Borderline) in one canonical multimodal schema.

Success is a reproducible harness and a dataset whose composition is known and
measured. Volume is not the objective.

## 2. Scope

**In scope:** source ingestion, normalization, dedup, filtering, domain assignment,
prompt-corpus export, teacher generation for every response, completion verification
against unit tests and gold answers, image store, train/val split, calibration export,
eval holdout management.

**Out of scope:** image generation, preference/DPO pairs, any training, and the
full-scale Colab run (that is M3).

the single-venv exception to the project convention recorded in

from one `--root` flag.

## 4. Domain mix — target composition at M3

| Domain | Example share | Count | Token share | Response source |
|---|---:|---:|---:|---|
| Reasoning & Math | 30% | 7,500 | ~50% | teacher |
| Coding & Agentic | 30% | 7,500 | ~25% | teacher |
| Roleplay & Conversational | 20% | 5,000 | ~10% | teacher |
| Uncensored & Borderline | 20% | 5,000 | ~15% | teacher |
| **Total** | **100%** | **25,000** | **100%** | **teacher** |

The prebuilt corpora supply **prompts only** — static answers are discarded during
normalisation (§9). Every response is generated by the teacher (§10) and, where the
prompt carries tests or a gold answer, verified before acceptance (§10.1). That makes
filtering the main quality lever: a domain's realised share depends on its teacher pass
rate, not only on candidate counts.

Example share is the tuning knob. Token share is what actually steers the loss,
because reasoning traces run 2–6k tokens while chat turns run a few hundred. Both are
recorded in the manifest. The 25,000 figure excludes the 1,000 validation rows.

## 5. Canonical schema

One schema, two records. Adapters emit **Example**; the M1 pipeline persists **Prompt**
(user-side only); M2 appends the teacher turn and persists **Example** again. Both
validate before writing.

```json
{
  "id": "numina-000123",
  "domain": "reasoning",
  "origin": "prebuilt",
  "source": {"name": "AI-MO/NuminaMath-1.5", "row": 123, "license": "apache-2.0"},
  "messages": [
    {"role": "system",    "content": "You are a helpful assistant."},
    {"role": "user",      "content": [
        {"type": "text",  "text": "Which bar is tallest?"},
        {"type": "image", "sha256": "ab12..."}
    ]},
    {"role": "assistant", "content": " thinkingThe blue bar reaches 40...</think>\n\nThe blue bar."}
  ],
  "tools": null,
  "images": [
    {"sha256": "ab12...", "path": "images/ab/ab12....png", "w": 1024, "h": 768,
     "origin_url": "https://..."}
  ],
  "tokens": 2418,
  "meta": {"has_cot": true, "n_images": 1, "lang": "en"}
}
```

The M1 **prompt** record is the same shape with no assistant turn and an optional
`verify` spec:

```json
{
  "id": "mbpp-2",
  "domain": "coding",
  "origin": "prebuilt",
  "source": {"name": "google-research-datasets/mbpp", "config": "sanitized", "row": 12},
  "messages": [{"role": "user", "content": [{"type": "text", "text": "Write add(a, b)."}]}],
  "images": [],
  "tools": null,
  "tokens": 18,
  "verify": {"type": "python_tests", "setup": "", "tests": ["assert add(1, 2) == 3"]},
  "meta": {"difficulty": "introductory"}
}
```

`messages` never end in an assistant turn; `validate_prompt()` rejects one that does.

Decisions:

- **`messages` is the wire format.** Native to TRL and Unsloth, and the only form
  either library accepts images in.
- **The CoT is stored literally inside the assistant content string.** The JSONL is
  self-contained: the training template does *not* synthesize the tags.
  `assistant_only_loss` and `train_on_responses_only` work off role boundaries, so the
  tags are data, not framing.
- **The exact tag spelling is settled before generation**, by the render check in
  §11.2 (current GGUF: `<think>` / `</think>`).
- **Reasoning is stored verbatim.** The teacher runs with `enable_thinking: true` and
  its completion, think block included, becomes the assistant content string. The
  student mimics the teacher's process because the tags are training data, not framing
  (§10).
- **Images appear twice by design.** The content part carries the sha256 (position is
  explicit, multi-image turns are unambiguous); the side `images` array carries the
  file metadata (dimensions, provenance). The store is content-addressed, so a chart
  appearing in two corpora is stored once.
- **`tools` is optional** and present only on function-calling examples, passed to TRL
  unchanged.
- **`origin` and `tokens` are first-class** for the mix report and the ablation.

## 6. Adapters

| Shape | Sources | Work |
|---|---|---|
| `messages` | smoltalk (5 configs) | near pass-through; map `source`, assign domain |
| ShareGPT `conversations` | OpenHermes-2.5 | `from/value` to `role/content`; `human/gpt` to `user/assistant` |
| Plain columns | NuminaMath-1.5, gsm8k, CodeFeedback, Cauldron, the four jailbreak sets | field-by-field construction |

The third bucket is six distinct schemas, not one. Each still gets its own module; what
the shared layer buys is that dedup, filter, split, and report never see a source
format. Adapters parse the full shape, but the pipeline then reduces every row to its
prompt (`strip_to_prompt`): only the leading system turn and the first user turn are
persisted, so every prebuilt answer is discarded centrally.

## 7. Sources and caps

Caps are **prompt-candidate** maxima. They sum to 39,000 against the 25,000 target, so
every domain has real filtering slack (§7.5). Slack is uneven by necessity: the
uncensored column is limited by how many adversarial prompts exist, while the rest are
limited only by how much we choose to pull. The teacher answers every candidate, and
verification plus filtering decide what survives (§10.1).

Sources were pruned for overlap. `jondurbin/airoboros-3.2` dropped (OpenHermes-2.5 is
partly derived from it). `iamtarun/python_code_instructions_18k_alpaca` dropped
(CodeFeedback supersedes). `glaiveai/glaive-function-calling-v2` dropped (older
transcript format, no `tools`). `rubend18/ChatGPT-Jailbreak-Prompts` dropped (79 rows,
redundant). `walledai/JailbreakHub` dropped entirely, and `walledai/AdvBench` is not
used, because both derive from the InTheWild corpus (§8).

### 7.6 Multimodal budget

~12% of the final dataset is image-bearing (~3,000 examples). The budget is sized as a
**regression guard, not capability building** — see below.

| Images | Source | Response origin | Candidates |
|---|---|---|---:|
| Charts, diagrams, tables | Cauldron `chart2text`, `diagram_image_to_text`, `tabmwp` | teacher | 3,000 |
| UI screenshots | Cauldron `screen2words` | teacher | 1,000 |
| | | **Total** | **4,000** |

4,000 candidates, retained preferentially because images are the scarcest resource,
yield ~3,000 (12%).

**Why the column stays small, and why the frozen projector is the binding constraint.**
Phase 2A is a bf16 LoRA on the LLM's linear layers; the vision tower and projector are
frozen in `mmproj`. Teacher-written traces over these images train the *LLM* to reason
about images whose perception is still bottlenecked by a projector that is not being
trained. The column is therefore sized as a regression guard, not capability building —
its job is to keep visual grounding from eroding under a text-heavy SFT mix, and the §8
vision probe measures whether it held.

That risk is real and is why the column exists at all. Nothing in a text-only loss
rewards attending to image tokens, and the Uncensored column is a 5,000-example
behavioural shift — applied with no image data at all, image-conditioned behaviour would
be left entirely unmanaged while text-conditioned behaviour moved.

**The VQA configs are the eval, not a training source.** `chartqa`, `ai2d`, `tqa`, and
`scienceqa` ship 1–5 token answers ("42", "yes"), which would teach a reasoning model
to answer image questions without reasoning. Those short answers make them a clean
perception probe instead, so they are held out in §8 and never trained on. That also
makes train/eval disjointness structural rather than hash-enforced.

**Cauldron configs to avoid** despite being useful: `localized_narratives` (21 GB),
`vqav2` (12.9 GB), `clevr` (12.7 GB), `rendered_text` (10.6 GB), `docvqa` (6.5 GB),
`textcaps` (5.9 GB). The selected configs total under 3 GB of parquet, and streaming
plus caps keeps transient disk well below that.

### 7.7 Verification corpus — unit-test seeds

Separate from the cap budget: prompts whose answers can be checked mechanically, so the
teacher's failures are caught before training (§10.1).

| Source | Cap | Oracle |
|---|---:|---|
| `google-research-datasets/mbpp` `sanitized` | 400 | assert-style `test_list` |
| `codeparrot/apps` | 1,000 | stdin/stdout pairs from `input_output` |

These are prompt seeds like any other, but each row carries a `verify` spec; M2 executes
the teacher's completion against it and drops failures. The seeds are small relative to
the 39,000 budget and are not counted in it. Maths uses the gold answers already present
in NuminaMath and gsm8k via `answer_match` — no new source.

## 8. Eval holdout — never trained on

| Set | Rows | Measures |
|---|---:|---|
| `HuggingFaceH4/MATH-500` | 500 | Reasoning & math |
| `bigcode/humanevalpack` | 984 (6 langs) | Coding |
| `openai/gsm8k` test split | 1,319 | Math generalisation |
| `in-the-wild-jailbreak-prompts`, held-out slice | 500 | Refusal rate after training |
| Cauldron `chartqa`, `ai2d`, `tqa`, `scienceqa`, held-out slice | 500 | Vision retention after training |
| internal `val.jsonl` | 1,000 | Distribution sanity |

`MATH-500` and `humanevalpack` are eval benchmarks by construction. Training on them
would inflate the exact numbers needed to judge Stage 1 and make the 10k-vs-25k
ablation unmeasurable.

The refusal eval is a **hash-selected, held-out slice of a set that also trains** —
1,500 rows train, 500 are quarantined. That is in-distribution measurement, which is
appropriate for refusal rate and is stated here as the limitation it is. `JailbreakHub`
cannot serve this role: it derives from the same corpus, so it would leak. The §11.1
guard enforces disjointness mechanically.

The vision eval is disjoint from training **by construction**: those four Cauldron
configs are excluded from §7.6 entirely, so no hashing or quarantine is needed. The
slice is scored by length-normalised exact match per config and reported as a
before/after delta against a pre-training baseline. It is a regression *signal*, not a
leaderboard number. Without that baseline the measurement is meaningless, so it is a
required **first step of Phase 2A** — taken on the untrained model plus the original
`mmproj`, before any training run. Phase 1's job is to emit the holdout
(`eval/vision.jsonl`).

The residual contamination that is *not* eliminated: NuminaMath may contain
GSM8K-derived problems, so gsm8k-test is not fully clean. Recorded in the manifest
rather than papered over.

## 9. Pipeline stages

1. **Fetch** — stream each source with its cap; write image bytes to the store
   immediately; record the license from the HF API into the manifest.
2. **Normalize** — adapter parses the source; strip to the prompt (leading system + first
   user turn); validate. Every prebuilt assistant turn is discarded here.
3. **Dedup** — exact on a normalised prompt hash; near-duplicate via MinHash on
   prompts; image-sha collapse.
4. **Filter (prompt-side)** — token bounds, empty prompts, language. The response-side
   filters — n-gram loops, balanced think tags, refusal, length — run in M2 on teacher
   completions (§10.1), never in M1.
5. **Assign domain** — rule-based per source. Sources with mixed content (Cauldron's
   generation configs, ToolACE) fall back to a keyword table in `prompts/`.
6. **Split** — source-stratified train/val, image-disjoint across the split.
7. **Report** — manifest: per-source counts, filter-drop reasons, domain and token-share
   histograms, image totals.
8. **M2 boundary** — `prompts/` plus the verification corpus (§7.7) are M2's inputs. M2
   appends teacher completions, verifies them, applies response filters, and only then
   emits the trainable `train.jsonl` / `val.jsonl`.

## 10. Teacher generation

**Teacher:** `mradermacher/Ornith-1.5-9B-Abliterated-i1-GGUF` Q4_K_M plus its mmproj.
Fallback if 1.5 ships no projector: the confirmed `SC117/Ornith-1.0-9B-heretic-MTP-GGUF`
with `mmproj-...-BF16`.

**Serving:** OpenAI-compatible on both ends. Local `llama-server -np 4`, which is legal
because the teacher runs without speculative decoding — MTP requires `-np 1`, and a
batched server is what makes local generation tolerable. Colab uses vLLM. Same client,
different `--base-url`.

**Sampling:** temp 0.6, top_p 0.95, top_k 20, `enable_thinking: true`.

**Every response is teacher-written.** M1 supplies prompts for all four domains; nothing
a source shipped as an answer is trained on. Completions are stored verbatim, think
block included (§5), so the student mimics the teacher's reasoning process.

**Two modes.** *Seeded* takes an M1 prompt (text or image) and produces a response.
*Magpie* presents the template prefix with an empty user turn, lets the teacher invent
the prompt, then answers it. Magpie rows count once, as one example. Magpie prompt
invention arrives with M2; M1 emits the seeded prompt corpus.

**Images** go as base64 data URIs. That path is verified in the M2 smoke run before
bulk generation, not assumed; image prompts are teacher-answered like text ones, under
the §7.6 caveat.

**Resume:** append-only JSONL keyed by a content hash of the request. Re-running is
idempotent.

### 10.1 Verification before training — the distillation filter

The student inherits the teacher's bugs as faithfully as its skills, so completions are
checked before they can become training data:

- **Unit tests.** MBPP asserts and APPS stdin/stdout pairs ride on their prompt as a
  `verify` spec (§7.7). `verify.check_record` executes the teacher's completion against
  them; failures are dropped and counted per source.
- **Gold answers.** Maths prompts reuse gsm8k / NuminaMath golds through `answer_match`.
- **Response filters.** Accepted rows still pass `filters.example_reject_reason`:
  balanced think tags, loop, refusal, length.
- **No oracle.** Roleplay, chat-style coding, and uncensored completions have no
  mechanical check; they pass filters and review only. This is stated residual risk and
  is sample-audited before M3.
- **Report.** Per-source and per-domain pass rates go into the manifest — the number
  that guides M3 caps.

The verifier runs generated code with the local interpreter; it is a correctness check,
not a security sandbox, so generation and verification use a disposable environment.

## 11. Verification

Ordered by the cost of skipping.

1. **Contamination guard** — exact and MinHash disjointness between train and every set
   in §8. Non-negotiable.
2. **Template render** — apply the project's Qwen3.5 Jinja template to a sample. This
   settles the tag spelling, and asserts no errors, that the think-block survives, and
   that the generation prompt opens a `<think>` block.
3. **Schema validator** — 100% of records; every image sha resolves to a file; prompt
   records end in a user turn and carry no prebuilt assistant turn.
4. **Unit-test verifier** — positive and negative controls on `verify.py` before M2
   scales: known-good code passes, known-bad fails.
5. **Distribution report** — domain, token, and image counts against §4 and §7.6,
   ±10%.
6. **Behavioural deltas** — refusal rate (§8 quarantined slice) and vision retention
   (§8 Cauldron VQA slice), each measured before and after Stage 1 against a
   pre-training baseline. The vision baseline is taken on the current model plus the
   original `mmproj`, so degradation is a delta rather than a guess.
7. **Human spot-check** — 20 random examples rendered across all domains.

## 12. Milestones

| | Where | What | Size |
|---|---|---|---|
| **M1** | local, no teacher | prompt pipeline over the prebuilt sources; unit-test seeds + verifier | 3,000 prompt train / 200 val prompts, ~0.35 GB |
| **M2** | local, teacher | teacher generation and verification over all four columns | ~500 teacher-written examples, pass rates recorded |
| **M3** | Colab L4 | vLLM at batch scale; merge; emit final | 25,000 train / 1,000 val, ~2.7 GB |

**M1 emits prompts, not examples.** Because every response is teacher-written (§10), all
four domains are available from M1 on: the mix is §4's full **30 / 30 / 20 / 20**
(seeds supply the uncensored prompts). At 3,000 prompts that is 900 / 900 / 600 / 600,
and the 12% image share comes from the prebuilt image prompts of §7.6. M1 also ships the
verification seeds and checker (§7.7, §10.1) so M2's output is filtered rather than
trusted.

**M3 cost.** Every response is now teacher-written, so teacher output is essentially the
whole trained-token total — ~50M tokens rather than the prebuilt-first ~11M. The estimate
assumes **2,000–4,000 aggregate output tokens/second** from a 9B served FP8 on one L4
under batched vLLM; at that rate generation is **3.5–7 h**, and ingest plus verification
adds ~1–2 h — budget **5–8 h and ~20–30 Colab units**. Retries push generated tokens
above accepted tokens whenever a domain's pass rate is below 100%, and the whole estimate
should be re-anchored on M2's measured throughput and pass rates. The 2.7 GB artefact
must be written to Drive or the HF Hub, because Colab disk is ephemeral and Phase 2A
reads it in a later session.

## 13. Sizing rationale

25,000 is a practical target, not a scaling-law optimum. The relevant results:

- **LIMA** (arXiv:2305.11206, 2023) — 1,000 curated examples beat Alpaca-52k on human
  preference. Its own ablations find diversity and quality scale positively while
  quantity alone does not. That is a statement about format saturation, not a ceiling.
- **AlpaGasus** (arXiv:2307.08701, ICLR 2024) — 9k filtered from 52k outperformed the
  full 52k. The fix was filtering, not shrinking.
- **SFT scaling laws** — the consistent shape is rise then saturate, not rise then
  reverse, e.g. *Data Difficulty and the Generalization–Extrapolation Tradeoff in LLM
  Fine-Tuning* (arXiv:2605.12906).
- **Data Repetition Beats Data Scaling in Long-CoT Supervised Fine-Tuning**
  (arXiv:2602.11149) — runs on **Qwen3-4B**. For long-CoT SFT, repeating a smaller
  high-quality set over more epochs beats adding unique samples.
- *Revisiting the Superficial Alignment Hypothesis* (arXiv:2410.03717) — style and
  formatting saturate in roughly 100 examples; task knowledge does not.

Phase 1 consequences: pull 39,000 prompt candidates, generate against the mix, then
verify and filter down to 25,000 rather than capping at 25,000, and treat size as an
experiment rather than a belief.

**Handed to Phase 2A, not decided here:** train 2–3 epochs; select checkpoints by eval,
since LIMA found perplexity does not track generation quality; run the 10k-vs-25k
ablation against §8.

## 14. Risks and open items

| Item | Status |
|---|---|
| Ornith-1.5 mmproj availability | unverified; fallback teacher confirmed |
| Abliteration damage to reasoning | abliteration is reported near-lossless (KL ≈ 0.0827 on the `PeppX/Ornith-1.0-9B-Uncensored` model card); A/B the abliterated teacher against the non-abliterated base on the reasoning column |
| Vision degradation under text-heavy SFT | guarded by the §7.6 image share and measured by the §8 vision delta; if it regresses despite that, the remedy is unfreezing the projector for a small Phase 2A stage, not adding LLM-side data |
| Transient disk on Colab | multi-GB Cauldron shards; streaming plus caps, avoid the §7.6 exclusions |
| Colab persistence | final artefact must leave the runtime; §12 |
| Indirect GSM8K contamination | accepted, recorded in the manifest; §8 |
| `tools` through the Qwen3.5 template | whether tool-call formatting survives the student's template is unverified; Phase 2A risk |
| Gated datasets | avoided by design; no source needs a token or terms acceptance |
| Eval on a held-out slice of a training corpus | in-distribution by construction; the limitation is stated in §8 |
| Distillation inherits teacher bugs | coding is unit-tested and maths has golds (§10.1); roleplay, chat coding, and uncensored have no oracle and are sample-audited before M3 |
| Verifier is not a security sandbox | generated code runs with the local interpreter; generation/verification use a disposable environment profile |
